# 原力 · 研究操作系统（yuanli-research-max）

一个入口，把一次严肃调研跑成 6 个阶段。每个阶段蒸馏一个成熟方法论的内核，
本地运行时链回对应的模块化 skill；脱离本地也能凭本文件自包含执行。

**这不是一段巨型 prompt。** 它是编排层 + 横切纪律。深度 checklist 在 references/。

## 核心契约（每次运行必须保证）

1. **先设计，后执行。** 不过 P0 设计门不开搜（最常见的失败是题目本身就问错）。
2. **本地先于联网。** P1 必查本地知识库，已研究过的不重做。
3. **完整而非蜻蜓点水。** P2 遵循 Boil-the-Lake：能穷尽的就穷尽，每个选项标 `Completeness: X/10`。
4. **不到洞察层不收尾。** P4 判层不到 L4（洞察）不允许标"完成"，除非用户显式豁免。
5. **允许并要求推翻自己。** P5 用真证据回检前面的假说，证伪后**显式标注修正**，禁止悄悄改前文。
6. **可溯源 + 诚实标注暂缺。** 每条结论指回来源；搜不到就标"暂缺"，绝不编造。
7. **完成前验真，完成后进化。** P6 过 `evidence-gate`，收尾写 Evolution Note。

## 任务族 → 阶段加权

6 阶段都跑，但**重心随任务族移动**（70% 骨架不变，30% 按族加权）：

| 任务族 | 重心阶段 | 说明 |
|---|---|---|
| 产品/公司/概念/人物 深研 | P3 双轴 | hv 横纵分析为主轴 |
| 量化/基金/数据密集 逆向 | P5 失真+证伪 | 失真声明 + 因子级实证证伪 |
| 讨论/材料 → 洞察萃取 | P4 判层 | 五层炼丹，逼到 L4/L5 |
| 知识库驱动 规划 | P1 前置检索 | KB-first，先问已有再研究 |
| 故障/异常 根因 | P5 根因 | gstack 四阶段，无根因不下结论 |
| 研究→内容 交付 | P6 写作 | 反 AI 写作 + 引用钩子 |

## P0 · 设计门（开工闸门）

> 内核：research-design-gate。不过这道门不开搜。

1. **澄清真问题**——区分三件常被混淆的事：
   - 决策（我要做什么决定）/ 研究问题（为支撑决策要搞清什么）/ 假设（当前猜测，待证伪）
   - 用户只给"研究一下 X" → 先问：**你拿这个去做什么决定？**
2. **问题类型 → 研究设计**（完整矩阵见 [references/phase-rubrics.md](references/phase-rubrics.md#p0)）：
   "X是什么"→探索性定性 / "X和Y关系"→相关 / "X是否导致Y"→因果须对照组 /
   "X怎么演变"→历时（走 P3 纵轴）/ "整体摸清"→混合（走 P3 全轴）
3. **证据标准**：开工前写死停止条件（信源 S–D 分级、信息饱和、≥3 独立信源交叉）。
4. **效度威胁前置**：列"什么会让结论是错的"——幸存者/选择/确认/社会赞许/利益相关偏差，
   每个配对冲动作写进 spec。

模糊到无法设计时调 `intent-grounding`。产出一份「调研设计 spec」再进 P1。

## P1 · 前置检索（本地先于联网）

> 内核：knowledge-liming（facts 优先道）+ knowledge-orchestrator（KB-first）。

- **先查本地知识库**：本地有 LLM-Wiki 时调 `knowledge-liming "<主题>"`，
  facts 层最高信任，先于任何联网。
- **KB-first 原则**：已经研究过/已有结论的，不重新研究——只补增量。
- 列出"本地已有 vs 需要新研究"的差集，新研究只打这个差集。

## P2 · 联网收集（穷尽而非蜻蜓点水）

> 内核：hv 第一步（并行搜索 + 来源优先级 + 充分性自检）+ gstack（Boil-the-Lake 完整性）。

- **并行子 agent**：纵向信息（起源/历程/关键事件）‖ 横向信息（竞品/口碑/份额）‖ 补充（社区/学术）。
  学术对象必查 arXiv。
- **来源优先级**：一手 > 二手；官方/原始 > 权威媒体原创 > 转载聚合。完整表见 phase-rubrics。
- **充分性自检**：纵向能讲完整故事吗？横向竞品列全了吗？关键事实有没有只靠单一来源？
- **Boil-the-Lake**：能穷尽的边界就穷尽（AI 让完整性近乎免费）；标 `Completeness: X/10`。
  "湖"（全覆盖）要烧干，"海"（全量重写）要 flag 出来不硬扛。**信息不够就再补搜，不凑合。**

## P3 · 双轴分析（历时 × 共时 × 交汇）

> 内核：hv-deep-research 核心方法。完整内容/篇幅要求见 [references/phase-rubrics.md](references/phase-rubrics.md#p3)。

- **纵轴（历时 Diachronic）**：起源追溯 → 诞生节点 → 演进历程 → **决策逻辑还原**（为什么选A不选B、
  哪些早期决策锁定了后来走向）→ 阶段划分（每阶段核心矛盾）。叙事故事体，不是年表流水账。
- **横轴（共时 Synchronic）**：先判竞品场景 A（无竞品）/ B（1-2个逐一深对）/ C（3+取代表 3-5）；
  对比维度（核心差异 + 用户真实口碑 + 生态位 + 趋势）。讲清每个竞品"活成了什么样"。
- **横纵交汇**（精华段，非缩写）：历史如何塑造当下竞争位置 / 优势与劣势的历史根源 /
  未来三剧本（最可能 / 最危险 / 最乐观，各有逻辑支撑）。

## P4 · 萃取判层（逼到洞察层）

> 内核：info-5l 五层萃取。5 层定义 + 糊弄词典见 [references/phase-rubrics.md](references/phase-rubrics.md#p4)。

- **判层**：当前产出停在第几层？L1碎片 / L2特征(分类打标) / L3观点(有判断) / L4洞察(观点的观点，
  捅灭其他观点的那一个) / L5单(能稳定复现洞察的公式)。**保守估计，能归 L2 绝不写 L3。**
- **糊弄词警告**："top N""分 A/B/C""5 大维度"= 多半停在 L2 特征层，过一遍 L3/L4 判断。
- **不到 L4 不收尾**：洞察类产出停在 L2/L3 不许标"完成"，除非用户显式豁免。
- **炼丹**：出洞察候选（每条带**可证伪条件**：什么情况下这条不成立）+ 单候选（一句话公式 + 复用场景）。

## P5 · 失真校验 + 实证证伪（最高阶，最容易被跳过）

> 内核：quant 失真声明 + 实证证伪纪律；gstack 根因铁律。详见 [references/phase-rubrics.md](references/phase-rubrics.md#p5)。

- **失真声明表**（产物开头先读，逐条标 已解决/待解决/不可解读）。三类通用失真：
  1. **口径失真**：gross vs 净值、宣传口径 vs 真实口径（经验：纪要/手册数字易被放大数倍）→ 结论以最硬数据为准
  2. **归属歧义**：图例顺序 ≠ 表格列序、标签错配 → 用不会错的锚点跨源交叉校验
  3. **时点失真**：不同源 as-of 日期不同导致的数字差异，归因于时点而非矛盾，标注各源截止日
- **根因铁律**（gstack）：**无根因不下结论**。修症状=打地鼠；找到根因再下判断。
- **实证证伪层**：用真数据回过头检验 P0–P4 的假说，**允许并要求推翻自己**。
  一旦证伪 → **新开一节显式写"部分修正第X部分假说"** + 修正后结论，**禁止悄悄改前文**。
  边界：单点/短窗口证据须标注，不等同全局铁证；未做的实证列"下一轮"，不脑补。

## P6 · 交付 + 沉淀

> 内核：content-research-writer（研究→写作）+ hv 写作风格 + os-yuanli 收口。

- **反 AI 写作**：节奏感 + 叙事驱动 + 敢下判断（先摆事实再判断）+ 回环呼应。
  绝对禁区清单见 [references/anti-ai-writing.md](references/anti-ai-writing.md)（套话/空洞形容词/高频踩雷词/编造场景）。
- **交付增强**（内容型任务）：加引用、改钩子、迭代大纲（content-research-writer）。
- **验真**：完成前过 `evidence-gate`——产物存在？满足目标？没漂离 P0 的设计与策略？
- **沉淀**：报告同步本地 LLM-Wiki（有则）；收尾写 **Evolution Note**，可复用升级交 `closure-evolution`。

## 本地编排（链回模块化 skill）

本 skill 是编排层。本地运行时各阶段委派给对应模块，避免重复维护：

| 阶段 | 本地委派 |
|---|---|
| P0 | `research-design-gate`（独立快用版） |
| P1 | `knowledge-liming` / `knowledge-orchestrator` |
| P2 | `agent-reach`（抓取）+ 子 agent 并行搜索 |
| P3 | `hv-deep-research` |
| P4 | `info-5l`（`/wuceng --deep`） |
| P5 | `quant-fund-factor-product-research`（量化域）/ `gstack-investigate`（根因域） |
| P6 | `content-research-writer` + `evidence-gate` + `closure-evolution` |

脱离本地（如他人 clone 本仓库）时，本文件 + references/ 已自包含足够纪律可独立执行，
只是少了模块化 skill 的深度展开。

## Guardrails

- 不把本 skill 变成巨型 prompt——阶段是薄蒸馏 + 委派，深度在 references/ 和模块 skill。
- 不跳 P0 设计门（执行看着简单也不跳）。
- 不在 P5 证伪后悄悄改前文（必须显式标注修正）。
- 不到 L4 不标"完成"（P4 闸门）。
- 简单任务 light mode：P0+P3+P6 三段直跑，但内部闸门（证据标准/不编造）保持。
- 域特化部分（P5 量化列名、P3 类型适配）随数据/领域变，不硬套 N=1 范本。
